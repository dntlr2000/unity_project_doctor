## Test Scaffold scope

- PLAN is read-only and binds the current project copy set, options, complete planned contents, and SHA-256 digests into one deterministic `planSha256`.
- APPLY requires the user-reviewed exact hash, revalidates current state, and uses create-new writes only. Existing files are never overwritten.
- The scaffold may add Runtime/EditMode asmdef files and required directory or `.meta` entries, but it does not create a passing test method, infer project-specific assembly references, or execute Unity.
- A Runtime asmdef changes an assembly boundary and therefore remains an explicit project mutation that requires review before APPLY.
- A partial transaction is accepted only if its own created entries are removed and the exact rollback postcondition is proven; otherwise the result remains blocked.

## Safety and scope

- Doctor remains a fully read-only static audit and never starts Unity.
- Baseline and EditMode pass only an external isolated project copy to the trusted Unity editor; the original Unity project is never used as `-projectPath`.
- Test Scaffold is the only Skill in this release that may modify the original project, and only through its explicit PLAN/hash/APPLY create-new contract.
- No Skill installs Unity, packages, PowerShell modules, certificate bundles, or external test frameworks.
- No automatic repair, debug workflow, PlayMode execution, Player Build, gameplay verification, runtime verification, or release-readiness claim is included.
- Incomplete schema, fingerprint, executable trust, source-editor, assembly, NUnit, process, or integrity evidence remains fail-closed and is never promoted to success.
