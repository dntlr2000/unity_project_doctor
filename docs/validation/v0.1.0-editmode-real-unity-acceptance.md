# Unity EditMode Verification 0.1.0 real-Unity acceptance gate

Status: **NOT RUN — PROCEDURE ONLY**

This document defines the later acceptance gate for the unreleased EditMode component. It does not claim that a signed Unity run succeeded.

## Historical precursor evidence

On 2026-08-22, a pre-hardening revision ran four meaningful NUnit test cases on signed Unity `6000.0.69f1`: 4 passed, 0 failed/error/inconclusive, and the original copy-set and Git metadata remained unchanged. The preserved result JSON SHA-256 was `7916a527af98b3d7ac598a149d4b71696c6e5ba74c3ed9e8c2df867e2bde61f1`. Because production code was subsequently hardened with selected-DLL, Baseline-diagnostic, import-log, and zero-test gates, that run is not final approval for the current implementation.

## Preconditions

- The implementation and fake/process/XML regression commit is green on Windows CI.
- The selected project uses exact Unity `6000.0.69f1`.
- Doctor reports at least one directly confirmed EditMode test assembly.
- The accepted Baseline isolation contains a non-empty `Library/ScriptAssemblies/<selected-name>.dll` for every selected assembly.
- The original project and its `.git` metadata can be hashed safely.
- No Unity process has the source project open.

## Explicit run

Open the exact Unity project root in a fresh Codex task and explicitly invoke:

~~~text
$unity-editmode-verification으로 현재 프로젝트의 확정된 EditMode 테스트를 검증해.
~~~

Do not run Unity manually and do not edit the project during the acceptance window.

For this repository's Windows acceptance environment, set `TEMP` and `TMP` to `E:\CodexTemp`, keep verification artifacts under `E:\CodexValidation`, and refuse the run if any Unity `projectPath`, log path, or isolation-copy path resolves to `C:`.

## Approval requirements

- `schemaVersion: 1.0.0` and `verifierVersion: 0.1.0`
- Baseline `1.1.0 / 0.1.3` accepted as `BASELINE_VERIFIED`
- Doctor `1.1.0 / 0.2.1` accepted with matching fingerprint
- current source and Baseline pre-Unity isolation fingerprints match the Doctor receipt exactly
- reusable isolation binding is `EXACT_MATCH` or `ROOT_IDE_GENERATED_FILES_ONLY`; the latter contains only structured project-root `.sln`, `.csproj`, or `.csproj.user` changes and no disallowed delta
- `preflight.selectedAssemblyBinariesPresent: true`, with a non-empty DLL record and SHA-256 for every selected assembly
- any rejected Baseline preserves its concrete primary cause, compiler diagnostics, and process-cleanup evidence rather than a generic handoff error
- exact signed Unity `6000.0.69f1` trust revalidated
- at least one passed test and zero failed/error/inconclusive tests
- skipped count preserved when nonzero
- process tree exit proven with zero active processes
- original copy-set `UNCHANGED`
- Git metadata `UNCHANGED`, `NOT_PRESENT`, or allowed ambient checkpoint additions only
- final status `EDITMODE_VERIFIED`

`ZERO_TESTS`/`NO_DISCOVERED_TEST_CASES`, a missing selected DLL, or malformed/import-failure Editor.log evidence is blocking and cannot satisfy this gate.

Approval is limited to Script Compilation and the selected confirmed EditMode test assemblies. PlayMode, Player Build, runtime, gameplay, and release readiness remain `NOT_VERIFIED`.

After a successful explicit run, preserve the result JSON and logs outside the project, calculate their SHA-256 values, anonymize local paths in a separate acceptance result, and only then consider a repository release.
