# Unity Project Doctor v0.2.0 실제 프로젝트 승인 기록

## 기록 정보

- 기록일: 2026-08-14
- 스캐너 버전: `0.2.0`
- JSON 스키마 버전: `1.0.0`
- 기계 판독 계약: [`schemas/unity-project-audit.schema.json`](../../schemas/unity-project-audit.schema.json)
- 검증 유형: 실제 Unity 프로젝트를 대상으로 한 읽기 전용 정적 점검
- 승인 결과: `APPROVED — PASS WITH KNOWN LIMITATION`

이 문서는 서로 다른 구성의 실제 Unity 프로젝트 세 개에서 관찰한 Unity Project Doctor v0.2.0 결과를 요약한다. 원본 scanner JSON 전체를 보관하는 증거 파일은 아니며, fixture 기반 자동 테스트를 대체하지 않는다.

## 승인 범위

이번 승인은 v0.2.0의 deterministic static scanner 범위에만 적용한다. Unity Editor, Unity Hub, batchmode, compiler, test runner, build pipeline 및 player/runtime 검증은 승인 범위에 포함하지 않는다.

## 공통 안전성 확인

세 프로젝트의 보고 결과에서 다음 안전 계약이 유지됐다.

- 대상 Unity 프로젝트에 파일, 로그, 보고서 또는 캐시를 생성하지 않았다.
- `Assets`, `Packages` 및 `ProjectSettings`를 수정하지 않았다.
- Unity Editor, Unity Hub 및 프로젝트 내부 실행 파일을 실행하지 않았다.
- 컴파일, 테스트, 빌드 및 런타임 프로세스를 실행하지 않았다.
- 외부 package 또는 PowerShell module을 설치하지 않았다.
- 실행하지 않은 동적 검증을 성공 또는 PASS로 표시하지 않았다.
- Git 검사를 완료하지 못한 프로젝트를 clean worktree로 표시하지 않았다.

모든 프로젝트에서 동적 검증 상태는 다음과 같았다.

| 검증 | 상태 |
| --- | --- |
| Compilation | `NOT_VERIFIED` |
| Tests | `NOT_VERIFIED` |
| Build | `NOT_VERIFIED` |
| Runtime | `NOT_VERIFIED` |

## 실제 프로젝트에서 확인된 동작 범위

- Unity `6000.0`과 `6000.5` 계열의 버전 정보 수집
- asmdef가 없는 프로젝트와 여러 asmdef가 있는 프로젝트 처리
- 선언된 테스트 어셈블리가 없는 경우와 EditMode/PlayMode 테스트 어셈블리가 있는 경우 구분
- 정상 Build Settings Scene과 누락된 비활성 Scene 구분
- AGENTS.md와 프로젝트 로컬 Skill의 존재 및 부재 처리
- 정상 Git worktree 검사와 안전 검사를 통과하지 못한 Git worktree의 보수적 저하 처리
- 검사 불가 상태를 `NOT_AVAILABLE`로 유지하고 성공 상태로 승격하지 않는 동작

## 알려진 제한

`Library` 또는 `Logs` 아래에 깊게 중첩된 임시 Unity 프로젝트나 PackageCache가 있으면 worktree reparse-point 사전 검사가 일부 항목을 안전하게 확인하지 못할 수 있다. 이 경우 v0.2.0은 프로젝트 밖으로 나갈 가능성을 배제할 수 없으므로 모든 Git 명령을 생략하고 Git 결과를 `NOT_AVAILABLE`로 보고한다.

이 동작은 잘못된 clean 결과를 방지하므로 안전 계약에는 부합하지만, 일반적인 실제 프로젝트에서도 Git 정보 수집이 보수적으로 생략될 수 있다는 기능상 제한이다. 안전 경계를 약화하지 않는 범위에서 후속 v0.2.x 개선 대상으로 다룬다.

## 승인 판정

**Unity Project Doctor v0.2.0 real-project acceptance: APPROVED — PASS WITH KNOWN LIMITATION**

승인 근거는 다음과 같다.

- 세 가지 서로 다른 실제 프로젝트 구성에서 정적 수집이 완료됐다.
- 경고와 검사 불가 상태가 관찰 증거에 맞게 보수적으로 보고됐다.
- Unity 프로젝트에 대한 읽기 전용 안전 계약이 유지됐다.
- 동적 검증 결과가 임의로 성공 처리되지 않았다.
- 승인된 출력 형상과 상태 enum이 JSON Schema Draft 2020-12 계약 및 fixture 회귀 테스트로 고정됐다.

Git 검사의 보수적 `NOT_AVAILABLE` 처리는 알려진 제한으로 승인한다. 이 승인은 아직 구현하지 않은 compile, EditMode/PlayMode test execution, Player Build, runtime 검증 또는 `unity-baseline-verification`의 완료를 의미하지 않는다.
