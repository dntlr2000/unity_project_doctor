# Unity Baseline Verification 0.1.1 real-Unity acceptance

This is a manual acceptance procedure for a later, explicitly approved run with a real signed Unity 6000.0.69f1 installation. It was not executed as part of the 0.1.1 hardening work.

## Preconditions

1. Obtain explicit approval for the exact source project, Doctor JSON destination, artifact root, and `Unity.exe` path.
2. Close the source project in Unity Editor. Other Unity projects may remain open.
3. Confirm the project `ProjectSettings/ProjectVersion.txt` identifies 6000.0.69f1.
4. Confirm the artifact root and Doctor JSON path are outside the source project and do not traverse a junction, symlink, or other reparse point.
5. Use the exact executable, normally `C:\Program Files\Unity\Hub\Editor\6000.0.69f1\Editor\Unity.exe`. Do not start Unity Hub.
6. Confirm the account can query `Win32_Process` command lines; inability to perform the exact source-editor preflight is a blocker.
7. Confirm the source tree is stable and no generator, package restore, source-control operation, or editor is changing it.

## Capture independent source evidence

Keep the evidence only in memory or under an external temporary directory. A suitable read-only file record is the ordinal list of each source-relative path, length, and SHA-256. Capture it immediately before Doctor and again after Baseline. Do not write a snapshot file into the project.

The Baseline result independently records complete pre/post tree SHA-256 summaries and exact added, removed, or changed paths.

## Generate the latest Doctor result

Run scanner 0.2.1 against the exact source root and write its sole stdout JSON outside the project:

~~~powershell
$project = "E:\Unity\ExampleProject"
$scanner = "E:\Playground\Pipelines\unity_agent_pipeline\skills\codex\unity-project-doctor\scripts\inspect-unity-project.ps1"
$doctorPath = Join-Path ([System.IO.Path]::GetTempPath()) "example-doctor-1.1.0.json"
$doctorStdout = & powershell.exe -NoProfile -ExecutionPolicy Bypass -File $scanner -ProjectRoot $project
[System.IO.File]::WriteAllText(
    $doctorPath,
    [string]::Join([Environment]::NewLine, [string[]]@($doctorStdout)),
    (New-Object System.Text.UTF8Encoding($false))
)
~~~

Review the JSON before proceeding:

- `schemaVersion` is 1.1.0.
- `scannerVersion` is 0.2.1.
- `projectRoot` is the exact normalized source root.
- `finalStatus` is `STATIC_AUDIT_COMPLETE` or `STATIC_AUDIT_COMPLETE_WITH_WARNINGS`.
- `blockedChecks` is empty.
- `projectFingerprint.status` is `COMPUTED`, `stabilityPasses` is 2, and `treeSha256` is present.
- compilation, tests, build, and runtime are all `NOT_VERIFIED`.

## Inspect Unity.exe trust before approval

~~~powershell
$unity = "C:\Program Files\Unity\Hub\Editor\6000.0.69f1\Editor\Unity.exe"
$item = Get-Item -LiteralPath $unity
$signature = Get-AuthenticodeSignature -LiteralPath $unity
[pscustomobject]@{
    FileVersion = $item.VersionInfo.FileVersion
    ProductVersion = $item.VersionInfo.ProductVersion
    CompanyName = $item.VersionInfo.CompanyName
    SignatureStatus = $signature.Status
    SignerSubject = $signature.SignerCertificate.Subject
    CertificateThumbprint = $signature.SignerCertificate.Thumbprint
    Sha256 = (Get-FileHash -LiteralPath $unity -Algorithm SHA256).Hash
}
~~~

Require ProductVersion 6000.0.69f1, Authenticode `Valid`, and a signer subject identifying Unity Technologies. Record the observed thumbprint; do not turn it into an undocumented permanent pin.

## Run only after explicit approval

~~~powershell
$verifier = "E:\Playground\Pipelines\unity_agent_pipeline\skills\codex\unity-baseline-verification\scripts\verify-unity-baseline.ps1"
$artifactRoot = Join-Path ([System.IO.Path]::GetTempPath()) "unity-baseline-acceptance"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $verifier `
  -ProjectRoot $project `
  -DoctorResultPath $doctorPath `
  -UnityExecutable $unity `
  -ArtifactsRoot $artifactRoot `
  -TimeoutSeconds 1800 `
  -Pretty
~~~

The command must print exactly one result JSON document. It must not start Hub, run tests, build a Player, enter PlayMode, or pass the source project to Unity.

## Acceptance review

Review the result JSON and external logs together:

1. `doctor.schemaValidated`, `doctor.accepted`, and `doctor.fingerprintMatched` are true.
2. `unity.signatureStatus` is `Valid`, `publisherMatched` is true, and the recorded versions, signer, thumbprint, and SHA-256 match the inspected executable.
3. `preflight.sourceEditorDetected` is false, `sourceSnapshotStable` is true, and all trusted paths are external/non-reparse.
4. `isolation.copyFingerprint.treeSha256` equals the accepted current-project fingerprint.
5. `unity.arguments` contains only the fixed batch/import arguments and the isolated `-projectPath`.
6. `processControl.processTreeExitVerified` is true and the final active-process count is zero.
7. The process exit code and Editor.log contain all explicit positive import/compile/shutdown markers, with no failure marker.
8. `originalProjectIntegrity.status` is `UNCHANGED`; before/after counts and tree SHA-256 are equal.
9. The independent post-run source file list/length/hash record equals its pre-run record.
10. `verification.tests`, `playerBuild`, `playMode`, and `runtime` remain `NOT_VERIFIED`.

Accept `BASELINE_VERIFIED` only when every required item above is supported by the JSON and logs. A timeout, signature problem, schema/fingerprint mismatch, inconclusive log, unproven process-tree exit, or source change is not acceptable.

## Explicitly outside this acceptance

- EditMode or PlayMode tests
- Player Build
- scene or gameplay execution
- runtime validation
- package installation or automatic package resolution repair
- API upgrade or project migration
- source modification, cleanup, or rollback
