## Regression addressed

Baseline 0.1.1 hashed the complete source tree for its final integrity decision even though Doctor fingerprinting and isolation copying excluded `.git`, generated directories, IDE metadata, and agent metadata. A successful isolated compile could therefore end as `ORIGINAL_PROJECT_CHANGED` when the Codex app added only checkpoint refs below:

~~~text
.git/refs/codex/turn-diffs/checkpoints/
~~~

Baseline 0.1.2 separates the exact copy-set content proof from in-project Git metadata evidence. It accepts checkpoint-namespace additions only when no existing Git metadata changed or disappeared. It continues to reject changes to HEAD, index, config, hooks, ordinary refs, objects, or any other Git path.

powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\unity-baseline-verification\run-tests.ps1

The Baseline suite must prove:

- a checkpoint-only addition leaves the Doctor/Baseline copy-set fingerprint unchanged;
- the Git metadata status is `AMBIENT_CODEX_CHECKPOINTS_ONLY`;
- HEAD, index, config, hook, ordinary-ref, object, existing-checkpoint modification/removal, and prefix-lookalike mutations classify as `CHANGED`;
- an in-project `.git` reparse point is rejected without traversal;
- source-content mutations alter the copy-set fingerprint;
- generated `Library` changes do not alter the copy-set fingerprint;
- the production entrypoint still rejects unsigned Unity substitutes;
- tests, Player Build, PlayMode, and runtime remain `NOT_VERIFIED`.
