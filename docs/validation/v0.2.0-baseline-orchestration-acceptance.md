# Unity Baseline Verification 0.2.0 one-command acceptance procedure

Acceptance status: **NOT YET EXECUTED**

This document defines the future signed-Unity approval gate for the Baseline 0.2.0 orchestration path. It does not claim that the new one-command flow has run against a real Unity Editor or received approval. The prior Baseline 0.1.2 result approves the unchanged low-level verifier trust core only.

## Frozen inputs

- Baseline component: `0.2.0`
- Orchestrator metadata: `0.1.0`
- Low-level verifier metadata: `0.1.2`
- Baseline result schema: `1.1.0`
- Doctor scanner: `0.2.1`
- Doctor schema: `1.1.0`
- Approved Unity version: `6000.0.69f1`
- Required Skill policy: `allow_implicit_invocation: false`

Do not perform this gate until the implementation commit has passed Doctor tests, Baseline direct tests, orchestration/resolver tests, PowerShell parse checks, and Windows CI without installing Unity or external packages.

## Explicit invocation

1. Close the target project's Unity Editor.
2. Open the exact Unity project root as the Codex working directory.
3. Record the source copy-set and `.git` state before invocation.
4. Invoke exactly:

   ~~~text
   $unity-baseline-verification으로 현재 프로젝트를 검증해.
   ~~~

5. Do not manually prepare or pass `DoctorResultPath`, `UnityExecutable`, `ArtifactsRoot`, a scanner path, or a verifier path for the default acceptance attempt.
6. If and only if automatic executable discovery returns a concrete missing-path blocker, verify the exact installed path and retry the orchestrator with `-UnityExecutable`. Do not choose another version or launch Unity Hub.

The Skill must run the bundled Doctor scanner directly, store its raw JSON outside the project, resolve only exact Unity `6000.0.69f1`, and invoke the existing low-level verifier. The orchestrator must never start Unity itself or synthesize a final status.

## Expected external artifacts

The generated Doctor evidence must use this external layout:

~~~text
<system-temp-or-explicit-external-root>/
└─ unity-baseline-orchestration-<guid>/
   ├─ doctor/
   │  ├─ unity-project-doctor.json
   │  └─ doctor-stderr.log
   └─ baseline/
      └─ unity-baseline-verification-<guid>/
         ├─ logs/
         ├─ results/unity-baseline-verification.json
         └─ project/
~~~

No artifact, report, cache, log, or temporary file may appear under the original project.

## Approval conditions

Approve only if the unmodified low-level result records all of the following:

- `finalStatus = BASELINE_VERIFIED`
- `schemaVersion = 1.1.0`
- `verifierVersion = 0.1.2`
- Doctor `schemaVersion = 1.1.0`, scanner `0.2.1`, `accepted = true`, and `fingerprintMatched = true`
- exact Unity `6000.0.69f1` with `signatureStatus = Valid` and a Unity Technologies signer
- `unity.processStarted = true`, `exitCode = 0`, and `timedOut = false`
- `processControl.processTreeExitVerified = true` and final active-process count `0`
- Editor.log classification `SUCCESS` with zero compiler errors
- `verification.scriptCompilation.status = VERIFIED_SUCCESS`
- `originalProjectIntegrity.status = UNCHANGED`
- `gitMetadataIntegrity.status = UNCHANGED` or `AMBIENT_CODEX_CHECKPOINTS_ONLY`
- no blockers
- tests, Player Build, PlayMode, and runtime all `NOT_VERIFIED`

Also compare the source and `.git` state recorded outside the verifier. Any unexpected source mutation, non-checkpoint Git delta, version substitution, scanner handoff failure, missing trust evidence, or inconclusive log evidence rejects approval.

## Evidence record

For a future public acceptance record, preserve or record:

- implementation commit SHA and branch;
- exact component versions above;
- final result JSON SHA-256;
- Doctor JSON SHA-256;
- Unity.exe SHA-256, signer subject, and certificate thumbprint;
- process, log, compilation, copy-set, and Git metadata status;
- whether automatic resolution or explicit override selected Unity.exe;
- confirmation that the original project was unchanged.

Remove machine-local user names and absolute project/artifact paths from any public document. Keep raw machine-local artifacts outside this repository.

## Rejection and scope

`BASELINE_FAILED`, `VERIFICATION_BLOCKED`, or `ORIGINAL_PROJECT_CHANGED` is not approval. Do not clean, repair, roll back, rerun with a trust bypass, or reinterpret the result.

This gate approves only isolated Unity script compilation. It does not verify EditMode tests, PlayMode tests, Player Builds, scenes, players, gameplay, runtime behavior, release readiness, or Unity versions other than `6000.0.69f1`.
